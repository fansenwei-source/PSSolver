# Phase 9 P9.7.4: pure Channel functional runtime

## Result

P9.7.4 connects the first executable batch-one Channel functional runtime for
the complete-stress Beris--Edwards model.  Its machine-readable authority is
[phase_9_p974_channel_functional_runtime.json](phase_9_p974_channel_functional_runtime.json).
The runtime is provisional and exported only through `pssolver.functional`;
the stable package-root API is unchanged.

This slice changes only PSSolver.  The independent PSSolver-Control project,
the frozen legacy `pssolver.control` oracle, production defaults, and the
frozen production modal Stokes solver are unchanged.  No H100 job is required
for this CPU implementation slice; installed-wheel CPU/H100 closure remains
P9.7.6.

## Pure state and flow map

The state remains the P9.7.1 tuple `(q_physical, q_spectral)`.  Each call
binds these tensors into fresh full-field storage, reconstructs the algebraic
flow, computes the nonlinear Q right-hand side, and returns new Q tensors.
Caller-owned state and controls are never mutated.  Progress counters,
diagnostics, pressure guesses, and Q-gradient caches are not state.

The functional flow path reuses the production complete-stress force model,
transforms, modal Helmholtz inverse, divergence, pressure gradient, projector,
and projected-Euler denominator.  It does not call the production
history-dependent pressure solve.  Instead it executes the P9.7.3 custom
implicit pressure adjoint with a zero initial guess on every call.  The
surrounding velocity calculation remains in the ordinary PyTorch graph, while
the pressure PCG iteration history is absent from the graph.

The activity control is the same non-negative cell-centered field declared in
P9.7.1.  The complete-stress model forms the physical product proportional to
`beta * activity * Q` before its projected divergence.  Observations are
input-state Q and the velocity/pressure generated by the current control.
Without a control, only terminal Q is available.

## Replay and gradient evidence

On the registered CPU float64 identity, repeated calls remain bitwise equal
after unrelated intervening calls and after fresh runtime construction.  The
functional pressure path never reads or writes the production warm-start
attribute, and both production Q-gradient caches are disabled on the private
functional adapter.

The CPU qualification establishes finite first-order gradients with respect
to both explicit Q state tensors and the activity field.  The activity
directional derivative agrees with a central finite difference.  Under a
matched zero-pressure-start policy, one functional observation and one Q step
are byte-for-byte identical to the production Channel ingredients.

These results qualify the local implementation boundary, not the independent
consumer, installed wheel, H100 memory behavior, or a scientific control
campaign.

## Durable checkpoint boundary

The production Channel checkpoint includes velocity, pressure, and a
history-dependent pressure warm start.  Those values do not exist in the
functional state and cannot be honestly fabricated without also supplying the
external control.  `ChannelActivityCheckpointBridge` therefore writes an
atomic functional-only Q-state format containing exact physical and spectral
Q, completed steps, state layout, and runtime identities.

The bridge can also import Q from an existing complete-stress production
checkpoint after checking the production runtime identity, backend restart
contract, tensor metadata, checksums, shapes, dtypes, and finiteness.  Export
is intentionally not claimed to be a production restart checkpoint.  This
asymmetry preserves the pure-state contract instead of hiding pressure history
or a previous control inside durable state.

## Compatibility and authorization boundary

The historical P9.7.1 non-executable declaration remains a frozen record of
what was available at that slice.  P9.7.4 adds a distinct explicit builder,
`build_channel_activity_functional_runtime()`, and does not change the
periodic `build_functional_runtime()` behavior.

P9.7.4 completes the provider-side executable CPU runtime.  P9.7.5 is the
next separately authorized boundary: migrate and qualify the second consumer
inside PSSolver-Control using only this provisional public module.  P9.7.4
does not authorize P9.7.5 implementation, an H100 job, P9.7.6 closure,
default promotion, larger batches, additional Channel boundary combinations,
or Phase 9 completion.
