# P7.7.12 CPU oracle portability recovery

Status: `LOCAL_RECOVERY_PENDING_HPCC_CPU_AND_H100`.

The first P7.7.12 HPCC attempt stopped before any H100 submission. All four
P7.7.11 cases passed direct/public byte identity, public-checkpoint restart,
direct/public resumed identity, uninterrupted/resumed identity, runtime
selection, and no-fallback checks. They failed only when their final raw NPY
SHA-256 values were compared with fingerprints generated by the desktop's
different Python, NumPy, and PyTorch build.

This was a test-contract error, not a numerical or scientific failure. Raw
FFT output bytes and NPY serialization are implementation fingerprints. They
are useful as exact regression oracles for the same recorded software build,
but they are not portable numerical tolerances across supported builds.

The recovered contract retains strict byte identity inside every observed
environment:

- direct and public continuous outputs must be identical;
- direct and public resumed outputs must be identical;
- resumed and uninterrupted outputs must be identical;
- runtime selection and no-fallback metadata must agree;
- when the full reference environment matches, the historical absolute hashes
  must still match exactly.

Only the invalid cross-environment absolute-hash requirement is removed. No
tolerance comparison is introduced, and no solver, model, boundary,
checkpoint, runtime default, or numerical implementation changes. The HPCC
fingerprints reported by the stopped run are retained in the machine record as
diagnostic evidence, not silently substituted for the desktop fingerprints.

Because the stopped run submitted zero H100 jobs, the corrected continuation
may still use the one formal P7.7.12 H100 submission after the recovered CPU
gate passes.

The local recovery passed 15 targeted tests and the complete suite of 2190
tests plus 8 subtests, with no failure, skip, or deselection. A dedicated test
exercises the mismatched-environment path, while a matching-environment hash
tamper remains a hard failure.
