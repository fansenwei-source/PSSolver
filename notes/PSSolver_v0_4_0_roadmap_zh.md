# PSSolver v0.4.0 目标与完成标准

本记录在 `S-16` 开始时建立，受已确认决定 `D-0014` 管辖，并沿用
`D-0011` 的不放宽门限、不新增 skip/xfail、逐步独立验收原则。开发线为
`dev/0.4`，运行时版本从本步起为 `0.4.0.dev0`，对照基线是已发布的
`v0.3.0`。

## 执行边界

- `S-16`、`S-17` 的数值输出必须与 `v0.3.0` 逐位相同，不运行 H100；
  如果必须改到 GPU 专用路径，先停止并把该部分转入 `S-19`。
- `S-18` 原则上也必须逐位相同；若确实做不到，必须在实现前登记容差、
  解释科学原因，并由用户另行决定。
- `S-19` 只做一轮参照 `S-09` 规模的预注册 H100 资格；资格失败后至多
  允许一个另行授权的诊断作业。
- `D-0013` 仅接受了 `v0.3.0` 的有界显存例外，该例外不延伸到 0.4。
- 所有正式发布的 `v0.2.x` 与 `v0.3.0` checkpoint 均保持只读兼容，
  不改写来源，并继续要求 restart 等价。

## 完成关卡

- `G-01`：S-16 至 S-18 的问题均已验证、由确认决定接受或明确延期，且
  没有未分流问题。
- `G-02`：R7/R9 的内部共享化完成；除 S-17 另行授权的接口工作外，公共
  接口不漂移；S-16 数值逐位不变。
- `G-03`：R8 按用户确认的保留策略实施；历史记录不改写；GitHub 新克隆
  可以在不增加 skip/xfail 的情况下完成测试。
- `G-04`：Control main 先完成 v0.3.0 同步与独立资格，再进入 R3/R6；
  S-17 数值逐位不变。
- `G-05`：全部 v0.2.x 与 v0.3.0 checkpoint fixture 继续可读，restart
  等价门禁通过。
- `G-06`：S-16/S-17 逐位不变；S-18 只有事先获批的容差可以例外；不放宽
  数值或科学门限。
- `G-07`：源码与 installed-wheel CPU、打包、公开 import、命令行入口、
  文档绑定和 provider identity 门禁全部通过，且没有新增 skip/xfail。
- `G-08`：按冻结合同完成一次集中 H100 资格，对照 v0.3.0，沿用已接受
  门限但不继承 D-0013 例外；失败时至多一个诊断作业。
- `G-09`：候选、正式资产、线上 Release 与发布后状态均通过独立只读验收。

本记录本身不授权 push、tag、GitHub Release、PyPI、HPCC、Slurm 或 H100。
